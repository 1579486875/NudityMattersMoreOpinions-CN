## 🆕 v1.2.1 更新了什么

### ① 修掉了 47 处「会在游戏里显示成代码」的坏占位符

原模组有几种占位符**根本不存在** —— 游戏不认它们，于是会把 `{PAWN_reflexive}`
这样的字面量**直接印在正文里**。原模组作者自己在 `Manifest.xml` 里承认过
「Removed `{PAWN_reflexive}` tag from descriptions」，但**没删干净**。

| 坏占位符 | 处数 | 修法 |
|---|---|---|
| `{PAWN_reflexive}` | 21 | → 「自己」（中文里最自然） |
| `{PAWN_objectivePossessive}` | 14 | → `{PAWN_possessive}`（他的/她的） |
| `{PAWN_namePossessive}` | 6 | → `{PAWN_nameShort}那…` / `…的`（按句意） |
| `{PAWN_nameShortPossories}` 等 4 种拼写错误 | 5 | → `{PAWN_nameShort}…` |
| `{Pawn_nameShort}`（大小写错） | 1 | → `{PAWN_nameShort}` |

判据不是猜的：把原版 `GrammarUtility.RulesForPawn` 提供的 token 清单逐字读出来，
再对照原模组源码，确认这几种**确实不在清单里**；同时核实 `{OTHERPAWN_*}` 与
`{PAWN_nameDef}` 是原版合法 token（所以**没有**去动它们）。

### ② 26 个翻译文件补上了 UTF-8 BOM

项目里原本 44 个文件带 BOM、26 个没带（这 26 个是 v1.2.0 新增的）。
现已全部统一，并且逐个验证「去掉 BOM 后与原文逐字节相同」—— 只加了 3 个字节。

### ③ 文档数字与实测对齐

| 项目 | 之前写的 | 实测 |
|---|---|---|
| 总键数（v1.2.0 当时口径） | 137,105 | **137,031** |
| 情境看法 | 8,246 | **8,241** |
| 互动日志 | 5,744 | **5,743** |

（正文 123,021 条、看法条目名称 5,214 条、生成器模板 2,729 条 —— 这三个经复核**本来就是对的**。）

> 📌 **本次修复后键数口径分成两处**（原因见第五节「第三个坑」）：
> `Languages\` 里 **5,866 个翻译键**，`OwnInjections\` 里 **125,744 条正文译文**（5,208 个容器）。
> 合计 **137,033 条译文**，与改造前逐条比对**一条不多、一条不少**。

### ④ 更正一处会误导人的说法

旧文档写「序号写错会让游戏抛异常、**导致整个翻译包失效**」。
反编译 `Verse.DefInjectionPackage.SetDefFieldAtPath` 后确认：**不会**。
越界只让**那一条**注入失败并计入翻译报告，同目录其它条目照常生效。
已按事实改写。

## 🆕 v1.2.0 更新了什么

### ① 补上了整整一块漏掉的内容

上一个大版本漏掉了原模组的**「看法生成器」模板** —— 那是 **2,729 条句段**，
程序会用它们拼出一句完整的看法：

> 「我注意到」+ 角色名 +「并被她彻底迷住了」

现在这些全部翻好了。**另外还补了 1,524 条看法条目名称。**

### ② 汉化包变成了「自包含」

以前这个汉化包依赖别人做的前置模组汉化，别人只下英文原版就会看到英文。

**现在不需要了** —— 本包已经把两个前置模组

* **Nudity Matters More**（裸体评价）
* **Nudity Matters More opinions**（更多看法）

的**全部文字**都包含了。不管你手上是**英文原版**还是别人做的汉化版，
装上这一个包就能显示完整中文。**本包不修改前置模组的任何文件。**

### ③ 设置界面终于也是中文了

原模组把设置界面的文字**直接写死在代码里**，翻译文件根本够不着 ——
所以以前的版本打开设置还是满屏英文。现在用界面补丁在运行时替换掉了：

- 「选项 → 模组设置 → 裸体评价 / 裸体评价：更多看法」里的**绝大多数选项**（下方「已知未覆盖」一节列了没接上的少数几处）
- 互动类型列表（淋浴、泡澡、桑拿、全裸医疗、人体艺术……）

### ④ 屏幕消息也汉化了

「XX 第一次看到 YY 裸体」「XX 的乳房第一次被人看到」这类消息，
以前会以英文弹在屏幕左上角。现在按 **17 种句式**全部译成中文。

### ⑤ 顺手修掉了原模组的 3 个缺陷

| 缺陷 | 后果 | 我们怎么修的 |
|---|---|---|
| 英文所有格是硬拼的 | 中文里显示成「张三's」这种夹生写法 | 把 61,647 处改成地道中文说法 |
| 特质翻译文件里颜色标签没转义 | **整个文件加载失败**，三个特质的描述全显示英文 | 用正确写法覆盖 |
| 「视奸狂」描述多了一个右大括号 | 文本格式化时会报错 | 已修正 |

### ⑥ 修掉了翻译里的 862 处「她的的」

`{PAWN_possessive}` 这类占位符在中文里展开后**自带「的」**（→「她的」）。
上一版有 862 处又多加了一个「的」，会显示成「她的的」—— 已全部修正。

## ❓ 常见问题

**Q1：装上了但还是英文，怎么办？**

按顺序检查这 4 件事：

1. **游戏语言是「简体中文」吗？** —— 选项 → 语言。**这是最常见的原因。**
2. **原模组装了吗？** 本汉化只提供翻译，原模组才是内容本体。
3. **两个都启用了吗？** 「模组」页面确认两个都勾上了。
4. **汉化排在原模组之后吗？** 顺序反了的话，原模组的英文会覆盖汉化。

---

**Q2：会不会影响存档 / 影响平衡？**

**不会。** 汉化包只替换**显示的文字**，不改任何数值、机制或数据。
存档完全不受影响，随时可以装卸。

---

**Q3：可以中途装上 / 卸载吗？**

可以，**不需要重开存档**。
装上之后新出现的看法就是中文；卸载之后回归英文。已有存档里的内容不受影响。

---

**Q4：我想切回英文怎么办？**

把游戏语言改成 English 即可 —— 本汉化只在简体中文下加载，
换成英文它就自动「隐身」了，原模组的英文内容照常显示。

---

**Q5：它和别的汉化包冲突吗？**

如果你同时装了别的同模组汉化，**后加载的那个会覆盖先加载的**。
建议只留一个，否则可能出现中英混杂。

---

**Q6：翻译质量怎么样？**

- 全部由人工校对，术语统一；
- 全部 137,033 条译文逐条检查过，没有一条残留英文；
- 还顺手修掉了原模组的一处本地化缺陷：
  它的所有格是**硬拼英文的 `'s`**，中文里会显示成「张三's」这种夹生写法 ——
  本汉化已把 **61,647 处**全部改成地道的中文「的」。

---

**Q7：原模组更新了，这个汉化还能用吗？**

大部分情况下能用。语言包是按**键名**匹配的：

- 原模组**新增**的内容 → 显示英文（汉化没覆盖到）；
- 原模组**改名/删除**的内容 → 对应的中文翻译会被忽略。

两种情况都**不会报错、不会崩溃**，只是有些条目会回退成英文。

## 🔧 出问题了怎么排查

### 第 ① 步：确认汉化被加载了

日志里搜 `NudityMattersMore`，看有没有加载相关的报错。

### 第 ② 步：确认目录结构正确

```
Mods\
└── 裸体评价更多看法-汉化修复\     ← 文件夹名可以不同
    ├── About\
    │   └── About.xml
    ├── Assemblies\
    │   └── NMMOpinionsChineseUI.dll
    ├── Languages\
    │   └── ChineseSimplified\
    │       ├── DefInjected\
    │       └── Keyed\
    └── OwnInjections\            ← 游戏不扫描，补丁 DLL 运行时读
        └── ChineseSimplified\
            └── DefInjected\
                └── ...
```

**最常见的问题**：解压时多套了一层文件夹，
导致 `About\About.xml` 不在正确的位置 —— 那样游戏根本不认这个模组。

### 第 ③ 步：检查加载顺序

本汉化必须**晚于**原模组加载。在「模组」页面把它往下拖到原模组之后。

### 第 ④ 步：提 Issue 时请附上

- 你的游戏语言设置；
- 原模组的版本；
- 看到的英文原文（截图或文字）；
- `Player.log` 里的相关行。

## 一、这是什么

《边缘世界》(RimWorld) 有个模组叫 **Nudity Matters More opinions**（裸体评价更多看法）。
它让殖民者之间产生大量**跟身体、穿着、裸露有关的看法**，直接影响彼此的好感度 ——
谁露了哪里、谁身材如何、某个部位长什么样，都会在社交界面里变成一条条的评价文字。

**问题是：原模组完全没有中文，全是英文。**

这个补丁就是它的**中文语言包**。装完之后，那些评价文字就都是中文了。

> ### ⚠️ 它不是独立模组
> 它**只包含翻译文本，不包含任何游戏内容**。
> **必须先装原模组，它才有意义**；单独装它，游戏里什么都看不到。

## 三、怎么装

### 第 1 步：先确认两个前置模组已经装好

在 Steam 创意工坊搜索并订阅：

| 前置模组 | 工坊里的名字 |
|---|---|
| 第 1 个 | `Nudity Matters More` |
| 第 2 个 | `Nudity Matters More opinions` |

### 第 2 步：下载并解压

到 [最新 Release](https://github.com/1579486875/NudityMattersMoreOpinions-CN/releases/latest)
下载 `NudityMattersMoreOpinions-CN-v1.2.8.zip`，解压。

解压后会得到**一个文件夹**，名字是：

```
裸体评价更多看法-简体汉化
```

### 第 3 步：把整个文件夹放进 Mods 目录

**放整个文件夹，不是放里面的文件。**

RimWorld 的 Mods 目录一般在：

```
D:\Steam\steamapps\common\RimWorld\Mods\
```

放好之后应该长这样：

```
Mods\
├── NudityMattersMore_opinions\        ← 原模组（你之前装的）
└── 裸体评价更多看法-简体汉化\           ← 本汉化
    ├── About\                         模组元数据
    ├── Assemblies\                    补丁 DLL（必需！删了正文就变回英文）
    ├── Languages\                     普通翻译键（游戏自己读）
    └── OwnInjections\                 自有清单（补丁 DLL 读，游戏不扫描）
```

### 第 4 步：在游戏里启用

打开游戏 → **模组** 页面 → 找到「**裸体评价更多看法 简体汉化**」→ 勾选它。

**关于排序**：它必须排在原模组**后面**。
`About.xml` 里已经写好了 `loadAfter`，正常情况下游戏会**自动排好**，不用手动调。

### 第 5 步：重启游戏

**翻译类改动，必须完全退出游戏再重进才会生效** —— 只回到主菜单是不够的。

### 第 6 步：进游戏看效果

**不需要新开档。** 翻译是纯文本替换，旧存档读进去直接就是中文。

进游戏后，点开任意殖民者 → **社交** 标签页，看到的中文就是本汉化的效果。

> 那是**逐条索引式**架构（13.2 万个键全塞进 `Languages\`）的代价。
> v1.2.7 改成「整列表注入」后，**游戏侧要注入的键从 137,033 降到 5,866**，
> 那 2.5 分钟不再存在 —— 旧文字留着会误导人，所以整节替换。

RimWorld 注入翻译时有一段 **O(N²)** 的重复检查
（`Verse.DefInjectionPackage.SetDefFieldAtPath`：每注入一个键都要重扫一遍表）。
**键越多越慢**，所以本汉化把绝大部分译文**挪出了游戏的那条路**：

| | 旧架构（≤ v1.2.6） | 现在的架构（v1.2.7 起） |
|---|---|---|
| 正文放在哪 | `Languages\`，13.2 万个**索引式**键（`<Def.opinionTexts.0>`、`.1`…） | `OwnInjections\`，5,208 个容器 / **125,744 条** |
| 谁读它 | 游戏自己 | `Assemblies\NMMOpinionsChineseUI.dll` 启动时读 |
| 游戏注入的键数 | 137,033 | **5,866** |
| 启动额外耗时 | 约 2.5 分钟（旧实测） | 键数降到约 **1/23**；新架构的启动耗时**本轮未实测**（未做计时） |

**为什么要绕这一圈**：`SetDefFieldAtPath` 里，整列表注入要求目标字段带
`[TranslationCanChangeCount]` 特性；上游的 `opinionTexts` / `texts` **没有**该特性
（反编译 `NudityMattersMore_opinions.dll` 实测 `TranslationCanChangeCountAttribute` 命中 0 处），
所以整列表直接放 `Languages\` 会被游戏**静默拒绝**（只记一条 loadError，不抛异常）。
改由自家 DLL 在 `[StaticConstructorOnStartup]` 里反射写回，才绕开这个限制。

**现在的开销是什么**：启动时多一次「读 47 个 XML + 逐容器反射赋值」，**一次**。
不进存档、不写盘、运行中零开销。**不影响**帧数、读档速度与日常操作。

> ⚠️ **`OwnInjections\` 不能删** —— 删了它，社交界面 12.5 万条正文会**全部退回英文**，
> 而游戏不会报错、不会崩，只在日志里留一条
> `[NMM 汉化] 自有清单目录不存在，注入跳过`。它和 `Assemblies\` 那个 DLL 是一对。

### ② 必须先装前置模组

本汉化只是语言包，**单独装它没有任何作用**。

### ③ 必须排在原模组之后

`loadAfter` 已经声明好了，正常会自动排。但如果你手动调整过模组顺序，
请确认它**不在原模组前面**。

### ④ 改完必须重启游戏

翻译改动只在**游戏启动时**加载一次。回到主菜单不够，要**完全退出再重进**。

### ⑤ 不与其他模组冲突

本汉化**含一个 Harmony 补丁 DLL**（`Assemblies\NMMOpinionsChineseUI.dll`），
它做两件事：把界面里**硬编码**的英文换成中文、以及在启动时把 `OwnInjections\`
里的正文清单反射写回 Def。除此之外不做任何事 ——
**不改游戏行为、不改原模组的任何文件、不写存档、不与其它模组抢方法**。

> 早先这里写的是「纯文本文件：不含代码、不含 dll」，那是 v1.2.3 以前的形态。
> 现在删掉那个 DLL，界面文字会变回英文、正文会全部退回英文（见注意事项 ①）。

### ⑥ 卸载很干净

直接删掉文件夹即可，**存档里不留任何残留数据**。

### ⑦ 想自己确认补丁完好

仓库附带自检工具，见下方[第六节](#六出问题了怎么办)。

## 五、汉化是怎么实现的（仅技术向，可跳过）

### 为什么原来的汉化包不生效

市面上有现成的翻译包，但在游戏里**一点效果都没有**。原因在这里。

#### 根因：RimWorld 是按「Def 的类型」去找翻译的

翻译文件必须放在这个位置：

```
Languages\ChineseSimplified\DefInjected\<Def 的类型全名>\<任意文件名>.xml
```

**目录名必须等于 Def 的类型全名。**

而本模组的看法用的**不是**原版的 `Def` 或 `ThoughtDef`，
是它自己定义的两个类型：

```
NudityMattersMore_opinions.OpinionDef_SexPart
NudityMattersMore_opinions.OpinionDef_Situational
```

但现成的翻译包，把译文放进了 `DefInjected\Def\` 目录。

**目录名对不上 → 游戏找不到对应类型的 Def → 整批翻译被丢弃。**

关键在于「**静默**」：**不报错、不提示、日志里一个字都没有**。
游戏里就是纯英文，你完全不知道问题出在哪。

#### 第三个坑（v1.2.7 才踩到的）：列表翻译要求字段带 [TranslationCanChangeCount]

老写法是「带下标的键名」，一条一个键：

```xml
<SomeDef.opinionTexts.0>第一条正文</SomeDef.opinionTexts.0>
<SomeDef.opinionTexts.1>第二条正文</SomeDef.opinionTexts.1>
```

它**能用** —— 因为每个键对应列表里的**一个字符串元素**，游戏按 `string` 处理。

v1.2.7 为了把键数从 13.7 万压到 1.1 万（缩短加载时间），改成了「整列表注入」：
一个键带一串 `<li>`：

```xml
<SomeDef.opinionTexts>
  <li>第一条正文</li>
  <li>第二条正文</li>
</SomeDef.opinionTexts>
```

**结果全部失效。** 根因在游戏源码 `Verse.DefInjectionPackage.SetDefFieldAtPath`：

```csharp
else if (!isPlaceholder && ensureFieldType != typeof(string)
         && !fieldNamed.HasAttribute<TranslationCanChangeCountAttribute>())
    loadErrors.Add("Tried to translate field ... doesn't have [TranslationCanChangeCount] ...");
else if (!isPlaceholder) { fieldNamed.SetValue(obj, value); result2 = true; }   // ← 只有这条才真正写入
```

整列表注入传进去的 `ensureFieldType` 是 `List<string>`（不是 `string`），
所以**必须**目标字段带 `[TranslationCanChangeCount]` 特性才允许写入。
而原模组的 `OpinionDef_SexPart.opinionTexts`、`BodyPartOpinionDef.texts` 都是裸的
`public List<string>`，**没有这个特性** —— 于是 **5,208 个容器、125,744 条正文译文全被拒绝**，
只在翻译报告里留下 5,208 条错误。（反编译 `NudityMattersMore_opinions.dll`，
再用 `search_attributes` 查 `Verse.TranslationCanChangeCountAttribute`：整个前置 DLL 命中 **0**。）

### 本汉化怎么解决：「自有清单 + 运行时注入」

1. 译文仍然放在**正确类型名**的目录下（这一点从一开始就是对的）：

   ```
   DefInjected\NudityMattersMore_opinions.OpinionDef_SexPart\
   DefInjected\NudityMattersMore_opinions.OpinionDef_Situational\
   ```

2. **普通键**（label、界面文字等 `string` 字段，共 **5,668** 个）留在
   `Languages\ChineseSimplified\` —— 游戏自己能正常处理。

3. **整列表键**（12.5 万条正文）搬到 `OwnInjections\ChineseSimplified\`。
   这个目录名**不在**游戏扫描的 `Defs\` / `Patches\` / `Languages\` 之列，
   游戏完全不会读它，因此**不会再产生任何翻译错误**。

4. 由本包自己的补丁 DLL（`Assemblies\NMMOpinionsChineseUI.dll` 里的 `OwnListInjector`）
   在**全部 Def 加载完成之后**（`[StaticConstructorOnStartup]` 时机）读这些清单，
   反射逐条写回 `Def.opinionTexts[i]`。

   好处：**体积与加载速度保持在 v1.2.7 的水平**（游戏侧只认 5,866 个键），
   同时正文真正变成中文。

5. 安全阀：逐条比对**条数**，条数不符就**整条容器跳过并记 Warning**（宁可漏译，绝不串行错位）；
   认不出 Def、字段类型不对、找不到模组目录等情况一律跳过，并把原因写进日志。

> ✅ 搬移前后已用脚本逐条比对：**131,365 条译文完全相同，0 丢失、0 错位**。

## 六、出问题了怎么办

### 装完进游戏还是英文？

按顺序排查：

| 检查 | 怎么确认 |
|---|---|
| **1. 重启游戏了吗** | 必须**完全退出**再重进，回主菜单不算 |
| **2. 前置模组装了吗** | 模组列表里要有那两个原模组 |
| **3. 本汉化启用了吗** | 模组页面里「裸体评价更多看法 简体汉化」要打勾 |
| **4. 排序对吗** | 确认它排在原模组之后（一般会自动排好） |
| **5. 前置模组有中文吗** | 如果原模组自己就是英文，那本汉化只管它自己的文字 |

### 想自己验证补丁完好无损

仓库自带一个自检工具：

```powershell
python tools\verify_patch.py
```

**不需要准备任何额外文件** —— 它会自己去读游戏目录里的原模组做比对。

检查 7 项：

| # | 检查项 | 防的是什么 |
|---|---|---|
| 1 | 原模组 Def 清单 | 读出原模组共有多少个 Def |
| 2 | 文件能否解析 | XML 有没有损坏 |
| 3 | **键名有效性** | 有没有指向不存在的 Def（悬空引用会让翻译失效） |
| 4 | **下标合法性** | 有没有越界（越界只让**那一条**失效，不连累整包） |
| 5 | 键唯一性 | 有没有同一个键被翻译两次 |
| 6 | 覆盖完整性 | 有没有漏译的正文 |
| 7 | XML 转义 | 有没有会破坏 XML 的裸符号 |

本仓库发布前已跑过。

> ⚠ **注意**：`verify_patch.py` 只扫描**原模组自己**的 Def 类型。
> `HediffDef` / `ThoughtDef` / `TraitDef` 这三类 Def 属于**前置模组**「裸体评价」
> （`dord.nuditymattersmore`），脚本没扫它，所以直接运行会在第 3、4 项上报「不通过」。
> 那是**脚本扫描范围**的问题，不是翻译数据的问题 —— 键本身完整（已用双向比对验证：
> 缺漏 0、孤儿 0）。要让它全绿，请在脚本的 `CAND_MOD` 里补上前置模组目录。

> 工具顶部有两行路径配置，换电脑时改那两行即可。

### 游戏启动太慢，不想等？

见 [注意事项 ①](#-启动开销旧架构的多等-25-分钟已不存在)。
本汉化自己那部分已经压到很小（游戏要注入的键只剩 5,866 个）。

需要留意的是**另一件事**：上游模组把 12 万条看法正文**写在 Def 里**，
游戏解析这些 Def 本身就要花时间 —— 那部分**装不装汉化都一样**，
见下方[「真正的瓶颈不在本汉化」](#真正的瓶颈不在本汉化)。

## ⚡ 性能开销（实测数据）

「模组会不会拖慢游戏」是很多人关心的，这里给出**实测数字**，不是估计。

本汉化的界面补丁只在**两处**会在游戏运行中执行代码，其余都是启动时改一遍常量：

| 补丁 | 触发时机 | 实测单次耗时 |
|---|---|---|
| 屏幕消息替换 | 每条屏幕消息一次 | **0.113 微秒**（非本模组的消息）／ 8.2 微秒（本模组的消息） |
| 设置界面选项名 | 设置界面里每个复选框一次 | **0.011 微秒**（一次字典查找） |
| 其余 5 类补丁 | 游戏启动、JIT 编译前 | **运行时零开销**（改的是内存里的常量） |

### 极端假设实测

本机实测（i7，各跑 100 万次取平均）：

**假设 1：1 秒内弹出 1000 条消息（现实中不可能）**

| | CPU 占用 |
|---|---|
| 加快速预筛之前 | 1.620% |
| **加快速预筛之后** | **0.011%**（提升 **143.7 倍**） |

> 「快速预筛」的原理：本模组的消息**必然**含 ` saw ` / ` was seen ` / ` were seen ` 之一，
> 所以先用最廉价的子串查找挡一下，不是就直接返回，不再跑那 17 条正则。
> 现实中的消息频率远低于这个假设（每分钟几条到几十条），实际开销可以忽略不计。

**假设 2：设置界面每帧画 100 个复选框**

每帧耗时 **0.001 毫秒**，占 60fps 单帧预算（16.67 毫秒）的 **0.0067%**。

### 真正的瓶颈不在本汉化

原模组把 **12 万条看法正文**写在 Def 里，游戏解析这些 Def 本身就要花时间。
这一份开销**与本汉化无关** —— 那些 Def 是上游模组自己的，装不装汉化都在。
而且它只在**启动时发生一次**，进游戏后不影响帧率。

> 本汉化自身那部分（游戏要注入的翻译键）在 v1.2.7 起只剩 **5,866** 个，
> 详见[注意事项 ①](#-启动开销旧架构的多等-25-分钟已不存在)。
