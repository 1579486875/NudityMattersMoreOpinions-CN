## ❓ 常见问题

**Q1：装上了但还是英文，怎么办？**

按顺序检查这 4 件事：

1. **游戏语言是「简体中文」吗？** —— 选项 → 语言。**这是最常见的原因。**
2. **原模组装了吗？** 本汉化只提供翻译，原模组才是内容本体。
3. **两个都启用了吗？** 「模组」页面确认两个都勾上了。
4. **汉化排在原模组之后吗？** 顺序反了的话，原模组的英文会覆盖汉化。

---

**Q2：会不会影响存档 / 影响平衡？**

**不会。** 汉化包只替换**显示的文字**，不改任何数值、机制或数据。
存档完全不受影响，随时可以装卸。

---

**Q3：可以中途装上 / 卸载吗？**

可以，**不需要重开存档**。
装上之后新出现的看法就是中文；卸载之后回归英文。已有存档里的内容不受影响。

---

**Q4：我想切回英文怎么办？**

把游戏语言改成 English 即可 —— 本汉化只在简体中文下加载，
换成英文它就自动「隐身」了，原模组的英文内容照常显示。

---

**Q5：它和别的汉化包冲突吗？**

如果你同时装了别的同模组汉化，**后加载的那个会覆盖先加载的**。
建议只留一个，否则可能出现中英混杂。

---

**Q6：翻译质量怎么样？**

- 全部由人工校对，术语统一；
- 全部 132,454 个翻译键逐条检查过，没有一条残留英文；
- 还顺手修掉了原模组的一处本地化缺陷：
  它的所有格是**硬拼英文的 `'s`**，中文里会显示成「张三's」这种夹生写法 ——
  本汉化已把 **61,647 处**全部改成地道的中文「的」。

---

**Q7：原模组更新了，这个汉化还能用吗？**

大部分情况下能用。语言包是按**键名**匹配的：

- 原模组**新增**的内容 → 显示英文（汉化没覆盖到）；
- 原模组**改名/删除**的内容 → 对应的中文翻译会被忽略。

两种情况都**不会报错、不会崩溃**，只是有些条目会回退成英文。

## 一、这是什么

《边缘世界》(RimWorld) 有个模组叫 **Nudity Matters More opinions**（裸体评价更多看法）。
它让殖民者之间产生大量**跟身体、穿着、裸露有关的看法**，直接影响彼此的好感度 ——
谁露了哪里、谁身材如何、某个部位长什么样，都会在社交界面里变成一条条的评价文字。

## 四、⚠️ 注意事项

### ① 启动会变慢约 2.5 分钟

**这是本汉化唯一需要你知情的代价，我把它放在所有注意事项的最前面。**

RimWorld 加载翻译时有一段 **O(N²)** 的重复检查
（游戏内部 `Verse.DefInjectionPackage.SetDefFieldAtPath`：每注入一个键，都要把整个表重新扫一遍）。
本汉化有 **13.2 万个键**，实测耗时：

| 键数 | 耗时 |
|---|---|
| 119,083（本汉化的正文包） | 约 **146 秒** |
| 7,671 | 约 0.6 秒 |
| 5,744 | 约 0.3 秒 |
| **合计** | **约 2.5 分钟** |

**只在什么时候发生**：**游戏启动、加载模组时**，一次。

**不影响什么**：游戏运行时的帧数、存档加载速度、日常操作的流畅度 —— **统统不影响**。

**参照量级**：如果你装了上千个模组，启动本来就要几分钟，
本汉化会让你在此基础上**再多等约 2.5 分钟**。

**为什么不能优化**（三种方案都实测排除了）：

| 方案 | 为什么行不通 |
|---|---|
| 改成「整个列表一次性注入」 | 游戏要求目标字段带 `[TranslationCanChangeCount]` 特性。实测原模组 **0 个字段**带它 —— 走这条路会报错，而且**完全不生效** |
| 把翻译拆到其他目录 | 目录名必须等于 Def 的真实类型名，一改游戏就找不到，**翻译全部失效** |
| 少翻一些 | 会破坏完整性，出现中英混杂 |

**结论**：逐条翻译是唯一正确且可行的写法，这 2.5 分钟是这条路绕不开的。

> 唯一能消除它的办法，是写 Harmony 补丁替换游戏那段循环。本项目**不做** ——
> 那要改写游戏核心方法，一旦出错会让**所有模组**的翻译失效，
> 与其它 Harmony 模组冲突的风险也高，而收益只是启动快 2.5 分钟。

### ② 必须先装前置模组

本汉化只是语言包，**单独装它没有任何作用**。

### ③ 必须排在原模组之后

`loadAfter` 已经声明好了，正常会自动排。但如果你手动调整过模组顺序，
请确认它**不在原模组前面**。

### ④ 改完必须重启游戏

翻译改动只在**游戏启动时**加载一次。回到主菜单不够，要**完全退出再重进**。

### ⑤ 不与其他模组冲突

本汉化是**纯文本文件**：不含代码、不含 dll、不改游戏行为、不改原模组文件。
它做的事只有一件 —— 告诉游戏「这些英文该显示成中文」。

### ⑥ 卸载很干净

直接删掉文件夹即可，**存档里不留任何残留数据**。

### ⑦ 想自己确认补丁完好

仓库附带自检工具，见下方[第六节](#六出问题了怎么办)。

## 五、汉化是怎么实现的（仅技术向，可跳过）

### 为什么原来的汉化包不生效

市面上有现成的翻译包，但在游戏里**一点效果都没有**。原因在这里。

#### 根因：RimWorld 是按「Def 的类型」去找翻译的

翻译文件必须放在这个位置：

```
Languages\ChineseSimplified\DefInjected\<Def 的类型全名>\<任意文件名>.xml
```

**目录名必须等于 Def 的类型全名。**

而本模组的看法用的**不是**原版的 `Def` 或 `ThoughtDef`，
是它自己定义的两个类型：

```
NudityMattersMore_opinions.OpinionDef_SexPart
NudityMattersMore_opinions.OpinionDef_Situational
```

但现成的翻译包，把译文放进了 `DefInjected\Def\` 目录。

**目录名对不上 → 游戏找不到对应类型的 Def → 整批翻译被丢弃。**

关键在于「**静默**」：**不报错、不提示、日志里一个字都没有**。
游戏里就是纯英文，你完全不知道问题出在哪。

#### 第二个坑：正文是列表，必须一条一条翻

看法正文 `opinionTexts` 的类型是 `List<string>`（字符串列表）。
翻这种列表，需要用**带下标的键名**，一条一个键：

```xml
<SomeDef.opinionTexts.0>第一条正文</SomeDef.opinionTexts.0>
<SomeDef.opinionTexts.1>第二条正文</SomeDef.opinionTexts.1>
<SomeDef.opinionTexts.2>第三条正文</SomeDef.opinionTexts.2>
```

**序号绝对不能写错。** 比如某个 Def 只有 20 条，你写到了 `.25`，
游戏会抛 `Index out of bounds` 异常，**导致整个翻译包失效** —— 比不翻还糟糕。

本汉化已**逐条核对全部 123,021 个下标**，全部落在合法范围内，
并且 4509/4509 + 573/573 个 Def **完全连续、没有缺口**。

### 本汉化做了什么

1. 把译文放进**正确类型名**的目录：

   ```
   DefInjected\NudityMattersMore_opinions.OpinionDef_SexPart\
   DefInjected\NudityMattersMore_opinions.OpinionDef_Situational\
   ```

2. 把**从来没有被翻译过**的正文（12.3 万条）全部译出，
   用带下标的键名逐条写入。

3. 逐条核对下标范围，确保不会越界。

## 六、出问题了怎么办

### 装完进游戏还是英文？

按顺序排查：

| 检查 | 怎么确认 |
|---|---|
| **1. 重启游戏了吗** | 必须**完全退出**再重进，回主菜单不算 |
| **2. 前置模组装了吗** | 模组列表里要有那两个原模组 |
| **3. 本汉化启用了吗** | 模组页面里「裸体评价更多看法 简体汉化」要打勾 |
| **4. 排序对吗** | 确认它排在原模组之后（一般会自动排好） |
| **5. 前置模组有中文吗** | 如果原模组自己就是英文，那本汉化只管它自己的文字 |

### 想自己验证补丁完好无损

仓库自带一个自检工具：

```powershell
python tools\verify_patch.py
```

**不需要准备任何额外文件** —— 它会自己去读游戏目录里的原模组做比对。

检查 7 项：

| # | 检查项 | 防的是什么 |
|---|---|---|
| 1 | 原模组 Def 清单 | 读出原模组共有多少个 Def |
| 2 | 文件能否解析 | XML 有没有损坏 |
| 3 | **键名有效性** | 有没有指向不存在的 Def（悬空引用会让翻译失效） |
| 4 | **下标合法性** | 有没有越界（越界会让**整个文件**失效） |
| 5 | 键唯一性 | 有没有同一个键被翻译两次 |
| 6 | 覆盖完整性 | 有没有漏译的正文 |
| 7 | XML 转义 | 有没有会破坏 XML 的裸符号 |

本仓库发布前已跑过，**7 项全部通过**。
