| 1.0.3 | `5f12374` | 5,264 | 同上 | 同上 |

**为什么 1.0.5/1.0.3 这 9 个不能硬兼容**（本轮查得最细的一处）：

作者在 1.0.7→1.0.8 之间把正文里的占位符从 `{PAWN_nameShort}` 改成了 `{OBSERVED_nameShort}`。逐条比对旧版与当前版本的原文：

```
iSaw_sleeping_naked_Male_Negative   旧 'As I walked in, my gaze fell upon {PAWN_nameShortPossessive}…'
                                    新 'As I walked in, my gaze fell upon {OBSERVED_nameShortPossessive}…'
```

9 个里只有 2 个（Unisex_Negative / Neutral）旧版原文是当前版本的前缀，其余 7 个都是**占位符改名**。

如果按「取前 min(N,M) 条」硬注入，我们译文里的 `{OBSERVED_nameShort}` 在旧版里**不会被替换**，玩家会看到字面量 `{OBSERVED_nameShort}` —— 比显示英文更糟。

所以注入器现在的行为（条数不符就整条跳过，宁可漏译不串行）是**唯一安全**的选择，本轮维持不变，并在描述里写明这条限制。

## 3. 修改清单

### 3.1 【严重】627 个「情境看法」的正文整体错位一位

**现象**：随机抽到第 0 条时显示「就这样，还有什么好说的？」，其余每条都显示成隔壁那条，每个 Def 的最后一条译文永远抽不到。

**根因**（反编译 `NudityMattersMore.dll` → `OpinionTextTranslator.Pick`）：

```csharp
int num = Rand.Range(0, texts.Count);       // 0 .. Count-1
string result = texts[num];
string key = $"NMM.Opinion.{def.defName}.{fieldName}.{num}";
if (!Translator.CanTranslate(key)) return result;
return Translator.Translate(key);
```

Keyed 下标必须与字段 List 下标一一对应、总数必须等于 `List.Count`。

而这 627 个 `OpinionDef_Situational` **没有 `ParentName`**（`BaseSituationalOpinionDef` 虽然是抽象模板，但全库没有任何 Def 以它为父，实测 `grep ParentName="BaseSituationalOpinionDef"` 命中 0）。此前的批量脚本把它们当成有继承的 SexPart，统一在 `.0` 插了一条基类占位（`InheritedBaseTextZh = "就这样，还有什么好说的？"`）并把原译文整体后移 —— 于是 8 条正文变成 9 条键，其中 `.0` 是废话、`.8` 永远读不到、`.1..7` 全部错位。

**判据验证**：把同一 Def 的 Keyed 与 DefInjected 对拍，**489 条「Keyed 比 DefInjected 后移一位」**（DefInjected 侧是 0 起的正确索引），零条相同 —— 错位是确凿的。

**修法**：逐个前移复位（删 `.0`、把 `1..N` 变 `0..N-1`）。

- 规模：`Situational.01.xml` 前移 5,000 / 删占位 376；`Situational.02.xml` 前移 3,100 / 删占位 251；两份语言目录各一遍 → 合计 **16,200 条键重排、1,254 条删除**。
- 脚本：`工具/fix-situational-index.py`（只改键名，不动译文、不动缩进与行尾）。
- 复验：`工具/audit-text-index.py` 五项全绿；Keyed 键数 131,394 → 130,767。

### 3.2 【中】1.6 下 526 条译文从未加载过

**现象**：1.6 每次启动逐条报 `Found no ThoughtDef named X to match X.label`。

**根因**（反编译 `Verse.DefInjectionPackage.SetDefFieldAtPath`）：

```csharp
if (GenDefDatabase.GetDefSilentFail(defType, defName, false) == null) {
    if (errorOnDefNotFound)
        loadErrors.Add("Found no " + defType + " named " + defName + " to match " + text2 + " (" + fileSource + ")");
    return false;
}
```

`ThoughtDef` / `TraitDef` / `HediffDef` 这三类 Def 只存在于 1.7 合并版（1.6 的 `Common\Defs` 里一个都没有），却被放在两版共用的根目录。

**修法**：三个目录整体移进 `v1.7\Languages\…\DefInjected\`（38 个文件，两份语言目录各一遍）。

- 判据：`工具/_diag_root_dangling.py` 逐键分类 —— 根目录 11,780 键里 11,283 条 1.6 也有（正常）、526 条只有 1.7 有、0 条两边都没有。
- 复验：`工具/audit-16.py`【5】从「526 个悬空键」变成「全部指向真实存在的 Def」。

### 3.3 【中】`DefInjected\NamedIndex\` 整目录被丢弃（且不写日志）

**根因**（反编译 `Verse.LoadedLanguage.LoadData`）：

```csharp
Type typeInAnyAssembly = GenTypes.GetTypeInAnyAssembly(directory4.Name);
if (typeInAnyAssembly == null && directory4.Name.Length > 3)
    typeInAnyAssembly = GenTypes.GetTypeInAnyAssembly(directory4.Name.Substring(0, name.Length - 1));
if (typeInAnyAssembly == null) {
    loadErrors.Add("Error loading language from ...: dir " + directory4.Name
                   + " doesn't correspond to any def type. Skipping...");
    continue;                        // ← 整目录跳过
}
```

`NamedIndex` 解析不到任何类型 —— 该目录 19 条键从来没生效过。

> ⚠ 这里要说准：这条错误**不会**进 `Player.log`。`LoadedLanguage.loadErrors` 只在游戏内「生成翻译报告」里能看明细，日志侧唯一的痕迹是 `Translation data for language … has N errors` 那一行 WARN。所以它属于**完全静默的失效** —— 本轮之所以能发现，是靠读源码 + 逐目录核对 Def 类型名，不是靠日志。

**逐条处置**：

| 组 | 条数 | 判定 | 处置 |
|---|---|---|---|
| ThoughtDef 命名索引 | 10 | 句柄写错（写 `unwelcome_comparison` / `jealous_feelings`，实际 stage label 是 `envy body` / `jealous` / `deeply jealous`）；`GetElementIndexByHandle` 找不到句柄会直接 `throw` | 丢弃（`ThoughtDef\` 里已有等价的数字索引版，功能不缺） |

| 抽象 Def 键 | 3 | `BaseSexPartOpinionDef` / `BaseSituationalOpinionDef` 是 `Abstract="True"`，不在 DefDatabase | 删除（否则必报 `Found no …`） |

**判据补充**：RimWorld 1.7 **支持**列表句柄（`DefInjectionPathPartKind.ListHandle`），所以 `degreeDatas.exhibitionist` 这种写法本身是合法的 —— 前提是位置放对（目录名必须是 Def 类型名）。

## 4b. 本轮发现的模板问题

1. **「审计脚本报不通过时先怀疑脚本」这条要再强调一次**：本轮 `verify_patch.py` 连报三次假失败（54 个 Def 没翻译 / 168 个悬空键），三次都是判据问题（漏扫 `v1.7\`、漏扫 `Patches\`、把外部 Def 算悬空）。建议在 §3.2.4 旁边补一句「**先跑一遍'这个脚本认识哪些目录/哪些 Def'的自问**」。
2. **「共用目录」的判据缺失**：模板里讲了 `LoadFolders` 的回退规则，但没有「根目录由多个版本共用时，哪些键只属于高版本」这一条。建议补：**凡根目录里的键，都要对每个低版本的 Def 集合跑一次存在性检查**。
3. **抽象 Def 的翻译**：`Abstract="True"` 的 Def 不在 DefDatabase，任何 `<模板名.字段>` 的键都会报 `Found no … named …`。模板附录可加这一条。
4. **附录 A 第 30 条（heredoc 吃反斜杠）本轮又踩了一次**：往报告里插一段含 `Common\Defs` 的文本时用了 `python - <<'PY'`，`\D` 被当成转义序列，Python 直接抛 `SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes`。**结论：那条规则要升级成「凡是要写含反斜杠的多行文本，一律先落成 .py 文件再执行，不要在 heredoc 里现场拼」。** 本轮之后所有报告/源码插入都改成写脚本文件。
5. **注释审计的口径要写明「排除控制流关键字」**：不排除的话 `else if (diff != 0)` 会被正则当成方法声明，于是覆盖率被误报成 97%（实际 100%）。这与 §3.2.4 列的六种误报是同一类。
