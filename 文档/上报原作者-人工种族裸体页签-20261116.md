# Nudity tab missing for races that hard-code their own inspectorTabs

Mod version 1.0.9, RimWorld 1.7.5011.

## What happens

Vanilla humans show the nudity tab. A number of race mods don't. Everything else about
the mod works — nudity is covered, streaking drops mood, opinions generate — the tab is
just not there.

It isn't age. I took a pawn from that race, edited them from 16 to 20, saved and
reloaded. Tab still missing.

## Why

The tab gets attached by a patch on the vanilla pawn base:

```
Defs/ThingDef[@Name="BasePawn"]/inspectorTabs
```

Vanilla `Human` is `<ThingDef Name="Human" ParentName="BasePawn">` and doesn't declare
`inspectorTabs` of its own, so it inherits that list. That's why humans are fine.

The races I looked at don't go through `BasePawn` at all. They start their own root and
copy the vanilla list by hand:

```xml
<ThingDef Name="HAR_Nearmaere_BasePawn" Abstract="True">
  ...
  <inspectorTabs>
    <li>ITab_Pawn_Health</li>
    <li>ITab_Pawn_Needs</li>
    ... the same 15 entries vanilla has ...
  </inspectorTabs>
```

The copied list doesn't include your tab, and since nothing in that chain touches
`BasePawn`, patching `BasePawn` never reaches them.

I went through 13 races from that series — Nearmare, Xenoorca, Idhale, Silkiera,
Neclose, Littluna, Solark, Saclean, Nexaga, Qualeela, Idearn, Chaoura, Outerm.
All 13 declare their own `inspectorTabs`, and none of them contain the tab.

So the tab never enters `inspectorTabs` in the first place. `ResolveReferences` never
puts it into `inspectorTabsResolved`, and `IsVisible` never gets called at all. Dropdown
tabs they do add themselves, like that series' appearance tab, show up normally.

## Suggested change

Rather than only patching `BasePawn`, walk the pawn defs once and add the tab wherever a
humanlike pawn tab list is missing it:

```csharp
foreach (var def in DefDatabase<ThingDef>.AllDefs)
{
    if (def.race == null) continue;
    var tabs = def.inspectorTabs;
    if (tabs == null || tabs.Count == 0) continue;           // inherits — leave alone
    if (!tabs.Contains(typeof(ITab_Pawn_Health))) continue;   // not a pawn tab list
    if (tabs.Contains(yourTabType)) continue;
    tabs.Add(yourTabType);
}
```

This has to run before `DefDatabase<ThingDef>.ResolveAllReferences()`, since that call
rebuilds `inspectorTabsResolved` from scratch. A postfix on
`LoadedLanguage.InjectIntoData_BeforeImpliedDefs` works — that's step 7 in
`PlayDataLoader.DoPlayLoad`, and `ResolveAllReferences` is step 9.

Testing for `ITab_Pawn_Health` keeps it to genuine pawn tab lists, so animals and items
are left alone, and the `Contains` check means races that already inherit correctly are
untouched.
