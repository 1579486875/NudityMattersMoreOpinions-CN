# R349 · 实机验证报告（2026-11-16）

> **本轮只做一件事**：把两个模组真正跑一次游戏，看它们在实机上的表现。
> 触发方式：`RimWorld.exe -quicktest`（不带 `-savedatafolder`，用默认配置）
> **结论**：两个模组在实机上都正常；游戏最后崩了，但**崩因是第三方 RimUnity 与新版引擎不兼容**，与本轮对象无关。

## 3. 崩溃分析：RimUnity vs 1.7.5011（与本轮对象无关）

```
10:06:00.508 INFO  Designator_DestroyItem constructor invoked, changing default label and description
10:06:01.003 ERROR [Vulkan] !!!CRASH!!!
10:06:02.832 CRIT  [Crash] === CRASH ===
System.MissingMethodException: Method not found:
  'Void Waylith.Rendering.PostFx.PostEffectPass.SetInput(Int32, Brutal.VulkanApi.VkImageView, Brutal.VulkanApi.VkSampler)'
- TRANSPILER Chezhou.RimUnity.Bloom: Waylith.Rendering.FrameRenderer.RecordFrame
             <- IEnumerable`1 RimUnity.Rendering.BloomHooks:PatchPasses(...)
```

**根因**：`RimUnity` 的 transpiler 按**旧签名**调用 `PostEffectPass.SetInput`，而 1.7.5011 改了这个方法 →
CLR 在 Vulkan 渲染层抛 `MissingMethodException` → 引擎崩。

**历史同源**：`About.xml` 里那段留档记的 2026-10-16 崩溃（`crash-20261016-132826.txt`）是同一个位置，
只是方向相反 —— 那次是**引擎快照落后于 RimUnity**，这次是**引擎跑到 RimUnity 前面去了**。

**影响面**：
- 崩溃文件 `Crashes\crash-20261116-100601.txt`（17.6 MB）
- `ModsConfig.xml` **一个字节没变**（45,704 B 逐字节相同）
- `-quicktest` 生成的是临时地图，**没有写任何主存档**

**不能简单停用 RimUnity**：`ZuoYao_RavenRace` 编译时引用了它的类型，停用会让整份程序集不可用、
大量 Def 解析失败（About 里那条警告仍然成立）。**这条需要你拍板**（见第 5 节）。

## 5. 需要你拍板的一条

> **RimUnity 与 1.7.5011 不兼容，现在每次启动都会在 Vulkan 层崩。**

| 选项 | 代价 |
|---|---|
| **等 RimUnity 作者更新** | 这段时间进不去游戏 |
| 临时停用 `RimUnity`（`chezhou.rimunity`） | `ZuoYao_RavenRace` 会因缺类型而整份程序集失效，大量 Def 解析失败（历史实测 3 分钟 5.7 万条 ERROR） |
| 回退游戏到 1.7.5005 | 要 Steam 的「测试版」分支里有旧版；而且会失去 5011 的新修复 |
| 单独给 RimUnity 打个「跳过 Bloom transpiler」的补丁 | 这是**改第三方模组行为**，且要写 transpiler 层面的守卫 —— 风险高于收益，我不建议 |

**我没有动它**（铁律第 2 条：不改第三方模组原始文件；且这条属 ⛔ 破坏意图档）。
