# 语言判定 · 判据表与订正记录（2026-11-16 · v1.5.8）

> 本文对应审查缺陷 **D-03**：两个补丁 DLL 判断「现在是不是中文环境」时的兜底写反了方向。
> 判据表的可执行版本在 `tools/audit-lang-detect.py`（已进 `full-regression.py` 闸门）。

---

## 一、问题是什么

两个 DLL 都有一句「这是不是中文环境」的判定，判定结果决定**要不要替换界面文字**：

| DLL | 方法 | 被多少处调用 |
|---|---|---|
| `NMMOpinionsChineseUI.dll` | `Zh.IsChineseLanguage(folderName, nativeName, englishName)` | 12 个 Transpiler/Prefix + `OwnListInjector.Run` |
| `GNH_NMM_Enhanced_ZH.dll` | `EnhancedText.IsChinese()` | 1 个 Transpiler |

这一句判错，玩家看到的东西就整个变样。而**旧版的兜底是反的**。

### 1.1 主补丁（`NMMOpinionsChineseUI`）

v1.5.7 的判据：

```
① folderName == "English"                     → false
② folderName 含 ChineseSimplified             → true
③ nativeName 含 简体 / 简中                    → true
④ englishName 含 Simplified Chinese           → true
⑤ folderName / nativeName / englishName 含繁体 → false
⑥ 以上全不命中                                 → **true**   ← 问题在这里
```

第 ⑥ 步的注释写着：

> 「宁可误替换也不能漏：这本来就是中文汉化包，装它的都是中文玩家。
> 万一判断失败而放行原文，玩家看到的就是满屏英文（正是上面那个 bug）。」

**这句话在「只考虑中文玩家」时是对的，但它漏掉了一个真实场景。**

### 1.2 增强界面（`GNH_NMM_Enhanced_ZH`）

v1.5.7 的判据更粗：

```
folderName == "English" 或含繁体  → false
其余一律                          → **true**
```

连 `ChineseSimplified` 都不查 —— 只要是「不是英文、不是繁体」就当中文。

## 二、谁会被误伤

判据的实际输入是 `Verse.LanguageDatabase.activeLanguage`：

| 输入 | `folderName` | `nativeName` | `englishName` | v1.5.7 结果 | 应该 |
|---|---|---|---|---|---|
| 简体中文 | `ChineseSimplified (简体中文)` | 简体中文 | ChineseSimplified | true | true ✅ |
| 繁体中文 | `ChineseTraditional (繁體中文)` | 繁體中文 | Traditional Chinese | false | false ✅ |
| 英文 | `English` | English | English | false | false ✅ |
| **俄语** | `Russian (Русский)` | Русский | Russian | **true** ❌ | false |
| **日语** | `Japanese (日本語)` | 日本語 | Japanese | **true** ❌ | false |
| **德语** | `German (Deutsch)` | Deutsch | German | **true** ❌ | false |
| **法语** | `French (Français)` | Français | French | **true** ❌ | false |
| **韩语 / 西语 / 葡语 / 波兰语……** | …… | …… | …… | **true** ❌ | false |

### 后果

玩家装了本包、然后切到俄语（多人共用一台机器、或中文玩家开英文档测试模组都很常见）：

- 12 个 Transpiler 与 `OwnListInjector` 一起把**界面标签和正文**换成中文；
- 但**框架性文本**（原模组自己的翻译、游戏本体文本）仍是俄语。

结果是「俄语框架 + 中文内容」的错乱组合 —— 比全英文更难读。

## 三、改成了什么

### 3.1 主补丁（v1.5.8）

在 ⑤ 与兜底之间**加一层正向中文判据**，然后把兜底改成 `false`：

```
① folderName == "English"                      → false
② folderName 含 ChineseSimplified              → true
③ nativeName 含 简体 / 简中                     → true
④ englishName 含 Simplified Chinese            → true
⑤ 含繁体（三个字段都查）                        → false
⑥ 【新】folderName 含 Chinese                   → true
⑦ 【新】englishName 含 Chinese                  → true
⑧ 【新】nativeName 含 中文 / 漢 / 汉            → true
⑨ 【改】以上全不命中                            → **false**
```

**为什么这样改是安全的**：⑥⑦⑧ 让「中文的识别面」比改之前**更宽**，
所以「漏判导致满屏英文」这个原来的担心不再成立。
改之前只有 ②③④ 三条路能判出中文；改之后有六条。

### 3.2 增强界面（v1.5.8）

同一口径（它只看 `folderName`）：

```
folderName == "English" 或含繁体        → false
folderName 含 Chinese / 中文 / 漢 / 汉   → true
其余                                    → false   ← 由 true 改来
```

两个 DLL **必须同时改**。只改一个的话，会出现「主补丁放行原文、增强界面却替换」的
分叉 —— 玩家看到「中文标签 + 外文内容」，比两边都替换更乱。

## 五、怎么复验

```powershell
# 判据表本身
python tools\audit-lang-detect.py

# 判据是否真的进了 DLL（反编译核对，不是看源码）
#   NMMOpinionsChineseUI.dll → Zh.IsChineseLanguage
#   末尾必须是 `return false;`，且前面有三条 `IndexOf("Chinese"|"中文"|"漢"|"汉")`
```

⚠ **镜像纪律**：`tools/audit-lang-detect.py` 里的两个 Python 函数是两份 C# 逻辑的逐行镜像。
**改 C# 就必须改它**，否则这张表会开始骗人。
