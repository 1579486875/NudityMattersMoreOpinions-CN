## 8. 第三轮追加（R359）：§4「缺 DLC / 缺目标模组」单条取证完成

### 8.1 问题

LocalFixes 的 22 个 XML 补丁**一个都没有 `MayRequire`**。那么「目标模组没装 / DLC 没装」时，
它们会不会刷 `Patch operation … failed` 红字？这是 §4 里唯一还没落到单条证据的一格。

### 8.2 逐补丁提取操作树

写了脚本把每个补丁的操作树打出来（标出每个节点属于「会返回 null 的守卫容器」还是「真执行」）：

| 分类 | 数量 | 形态 |
|---|---|---|
| **全部在守卫容器内** | **8 个** | `PatchOperationConditional` / `FindMod` / `Test` 包住，缺目标时**返回 null → 不执行** |
| **裸操作 + `success=Always`** | **14 个** | 操作会执行，但**强制算成功** |

那 14 个的裸操作共 49 处，**每一处都带 `<success>Always</success>`**（不是靠外层）。

### 8.3 反编译证实 `success=Always` 的语义

`Verse.PatchOperation.Apply(XmlDocument)`（1.7.5011 实测）：
```csharp
bool flag = ApplyWorker(xml);                 // 真执行
if (success == Success.Always)      flag = true;    // ← 无论成败强制成功
else if (success == Success.Never)  flag = false;
else if (success == Success.Invert) flag = !flag;
if (flag) neverSucceeded = false;                   // ← 关键
return flag;
```

`Verse.PatchOperation.Complete(string)`：
```csharp
if (neverSucceeded)                                 // ← 只有「从未成功过」才报
    Log.Error($"[{modIdentifier}] Patch operation {this} failed\nfile: {sourceFile}");
```

⇒ `success=Always` → `flag=true` → `neverSucceeded=false` → **`Complete` 不会报**。

### 8.4 与实机日志对照（反向验证）

如果我们的补丁里有一处「裸操作且没有 `success=Always`」，缺目标时就该像下面这样报：

```
[OA]Ratkin Gene Expand            Patch operation PatchOperationRemove(…) failed
[TSIND Garage Doors QA]           Patch operation XmlExtensions.UseSetting failed
[Better Architect Menu | Tweaks]  Patch operation ModSettingsFramework.PatchOperationModOption(…) failed
[外星人SA纹理适配生物大师1.7自改整合版]  Patch operation PatchOperationFindMod(Mugirl Race) failed
[Raven Race - Embers in Shadow]   Patch operation PatchOperationSequence(count=11, …) failed
```

**这 6 条全是第三方模组的**，我们的 **0 条**。这从反面印证了第 8.2/8.3 节的结论。

### 8.5 结论

| 项 | 结果 |
|---|---|
| 22 个 XML 补丁 | **全部能安全跳过**（8 靠容器守卫、14 靠 `success=Always`） |
| 缺 DLC / 缺目标模组时 | **不会刷红字**（反编译 + 实机双向证实） |
| 是否需要补 `MayRequire` | **不需要** —— 那是「提前不求值」的优化，而已有的两种守卫已经保证不出错 |

⚠ 一条方法论备注：`success=Always` 与 `Conditional` 守卫**不等价** ——
前者会让操作**真跑一次**（`ApplyWorker` 照常执行，只是结果被忽略），后者根本不跑。
对纯 XML 修改操作（Remove/Replace/Add）两者都安全；但若操作有副作用（比如启动某段代码），
就只能用 `Conditional`。本仓 22 个补丁全是纯 XML 修改，所以两者都可。
