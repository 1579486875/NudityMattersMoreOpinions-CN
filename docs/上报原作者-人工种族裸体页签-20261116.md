# Opinions tab missing for races whose FleshType contains "Android"

Mod version 1.0.9, RimWorld 1.7.5011, with RimJobWorld installed.

## The race mod involved

Reported against the Aya race series — called 人工种族 ("artificial race") in the Chinese
community. The shared premise mod it all depends on is:

https://steamcommunity.com/sharedfiles/filedetails/?id=3505571618

Any race from that series should reproduce it. The thing to look at is that race's
`FleshType` defName — if it contains `Android`, it hits the branch explained below.

## What happens

Vanilla humans get the nudity tab. Some race mods don't. The tab is just not there,
while everything else about the mod works fine — nudity is still covered, streaking
still gives the mood hit, opinion texts still generate.

Age isn't it. I took a 16-year-old of that race, edited them to 20 in the character
editor, saved and reloaded. Tab still missing.

## Why

`ITab_Pawn_NMMOpinions.IsVisible` is:

```csharp
return canDoLoving && isHuman && !isEntityOrGhoul;
```

`canDoLoving` comes from `rjw.xxx.can_do_loving`, which starts with:

```csharp
if (is_mechanoid(pawn)) return false;
```

and `rjw.xxx.is_mechanoid` checks FleshType by substring:

```csharp
if (AndroidsCompatibility.IsAndroid(pawn)) return false;
return pawn.RaceProps.IsMechanoid
    || pawn.RaceProps.FleshType == FleshTypeDefOf.Mechanoid
    || pawn.RaceProps.FleshType.corpseCategory.ToString().Contains("CorpsesMechanoid")
    || pawn.RaceProps.FleshType.defName.Contains("GR_Mechanoid")
    || pawn.RaceProps.FleshType.defName.Contains("MechanisedInfantry")
    || pawn.RaceProps.FleshType.defName.Contains("Android");
```

The exemption only matches one extension type:

```csharp
// rjw.AndroidsCompatibility cctor
typeName = "Androids.SexualizeAndroidRJW";
```

So any race whose `FleshType.defName` contains `Android` — apart from Androids itself —
is treated as a mechanoid. `can_do_loving` returns false on that first line and the tab
never appears.

The rest of the mod is unaffected because the nudity checks never call `is_mechanoid`
anywhere; only this tab does.

## Suggested change

The tab has nothing to do with whether a pawn can have sex. Dropping that term:

```csharp
return isHuman && !isEntityOrGhoul;
```

If the check was there to keep minors out, age is the thing to test:

```csharp
bool adult = pawn.ageTracker.CurLifeStage.reproductive
             || pawn.ageTracker.Growth >= 1f;
return adult && isHuman && !isEntityOrGhoul;
```

Either version stops depending on RJW's mechanoid detection.

## Two side notes

If RJW isn't loaded at all, `IsVisible` fails at JIT time and the tab vanishes for
every race including humans. RJW is a hard dependency so it probably doesn't matter
much, but the symptom is confusing when it happens.

Separately, `ElToro.MAddon` makes the same call in `MCPTargetGrantUtility.TryGrant`:

```csharp
if (p.Faction == Faction.OfPlayer && xxx.is_mechanoid(p) && defs.SubcoreBioprinting_RP.IsFinished)
    p.abilities.GainAbility(defs.MCPTarget);
```

so a misjudged race also quietly picks up the bioprinter ability. That one is probably
worth passing along to its author as well.
